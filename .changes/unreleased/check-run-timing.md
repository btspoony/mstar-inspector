- **The check run appears when the review starts and finishes about a minute after it publishes**: the Check attempt is now claimed at admission — after the in-flight guard accepts the message, before the container is acquired and the PR is cloned — using the delivery's head SHA or the PR head watermark, so a cold sandbox no longer hides the first five minutes of a run. When the authoritative checkout disagrees with that claim (a force-push mid-flight), the early run is closed as `superseded` and a fresh attempt is claimed at the checked-out commit; a duplicate delivery that hits idempotency closes its run before acking. The claim now sits at the start of the existing 15-minute execution window — the Cloudflare Queues per-invocation cap, neither widened nor a tuning knob — so that window covers the container phase without being stretched.

- **Giving up on the terminal `checks.update` now releases the attempt instead of waiting out the deadline**: when the consumer's terminalize budget elapses, the hook throws, or the checkout contradicts the claimed head, the lifecycle freezes a terminal intent only where none is frozen yet — a proof-derived conclusion and its exact summary are never replaced — and hands the attempt to recovery with `remote-unconfirmed` and the first 60 s backoff rung. No remote request, and a no-op if recovery already claimed it. The Check recovery reconciler also runs on its own every-minute cron (declared for the top-level Worker and every named environment) while the failure sweep and the publication reconciler stay on fifteen minutes, so a released attempt closes about one to two minutes later instead of at the next quarter hour after its execution deadline. Give-ups are diagnosable through the structured `check_terminalize_budget_exceeded`, `check_terminalize_failed` and `check_abandon_released` lines.

- **检查在审查开始时出现、并在发布后约一分钟内结束**：Check 尝试改为在准入时认领——在并发守卫接受消息之后、创建容器与克隆 PR 之前——使用投递携带的 head SHA 或 PR 头水位，因此冷启动沙箱不再掩盖一次运行最初五分钟的状态。若权威检出的提交与该认领不一致（处理期间发生 force-push），早期运行会以 `superseded` 关闭，并在实际检出的提交上重新认领；命中幂等的重复投递会先关闭其运行再 ack。认领现在位于既有 15 分钟执行窗口的开端（Cloudflare Queues 单次调用上限，既不放宽也不是可调项），因此该窗口覆盖容器阶段而不被拉长。

- **放弃终端 `checks.update` 时立即释放尝试，而不是等执行截止**：当消费方的 terminalize 预算耗尽、hook 抛出异常，或检出的提交与已认领的 head 不一致时，生命周期只在尚未冻结任何结论时才写入兜底意图（`superseded` 失败或通用的未确认失败），且该条件写在 UPDATE 谓词里——已冻结的结论（例如来自发布证明的成功）及其精确摘要绝不会被覆盖。随后以 `remote-unconfirmed` 与第一档 60 秒退避把尝试交还恢复通道：不发送任何远端请求，若恢复通道已接管则为空操作。Check 恢复协调器新增独立的每分钟 cron（顶层 Worker 与每个具名环境都要声明），失败巡检与发布协调器仍保持十五分钟，因此被释放的尝试通常约一到两分钟后收敛（第一档退避 + 下一次每分钟触发），而不是在执行截止后的下一个整刻钟。放弃路径可通过结构化日志 `check_terminalize_budget_exceeded`、`check_terminalize_failed`、`check_abandon_released` 诊断。
