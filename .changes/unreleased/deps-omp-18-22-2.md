- **omp SDK 18.22.2 and harness engine 4.7.3 across root, runner and the review image**: the root manifest's `@oh-my-pi/pi-coding-agent` pin moves from `18.18.6` to `18.22.2`, `packages/runner`'s from `18.18.1` to `18.22.2`, and the engine pins from `^4.7.0`/`4.7.0` to `^4.7.3`/`4.7.3`; both lockfiles regenerate. The runner learns the SDK's new run lifecycle: `agent_end` is now emitted once, when nothing can resume the run, and a model loop that stops while the run continues emits `agent_pause` instead. The deep parent turn reads a pause from `agent_pause` (and waits for the resume only when the pause names outside work) where it used to read a non-terminal `agent_end`, so a parked deep review is still awaited rather than published as a stopped one. The regenerated provider catalog follows omp's own registry: it is the measurement of what omp now ships.
- **The image rebuild gate records a fingerprint instead of asking for a comment**: `sandbox-image/Dockerfile` carried 51 `# rebuild:` prose lines, each present only to change the file's bytes so `wrangler` re-hashes it. One `# image-inputs:` line now hashes every copied source plus the container block, and `bun scripts/check-image-inputs.ts --base origin/main --write` is the whole repair. A stale line fails the check; the prose is gone.
- **Command Code's model list is measured, not remembered**: the regenerated catalog carries 41 chat-completions ids, 12 anthropic-messages ids and 47 responses ids for the provider, replacing the previous 50 / 11 / 35 split from the 18.18.1 snapshot. The counts come from omp's bundled registry verbatim; nothing is hand-edited.

- **omp SDK 升至 18.22.2、harness engine 升至 4.7.3（根、runner 与审查镜像）**：根 manifest 的 `@oh-my-pi/pi-coding-agent` pin 从 `18.18.6` 升到 `18.22.2`，`packages/runner` 从 `18.18.1` 升到 `18.22.2`，engine pin 从 `^4.7.0`/`4.7.0` 升到 `^4.7.3`/`4.7.3`；两个 lock 均重新生成。runner 适配 SDK 新的 run 生命周期：`agent_end` 现在只在整轮再无可恢复工作时发一次，而 run 仍在继续时停下的模型循环改发 `agent_pause`。deep parent turn 从 `agent_pause` 读取暂停（仅当该暂停指向外部工作时才等待恢复），不再读非终态 `agent_end`，因此被挂起的 deep review 仍会被等待，而不会被当作已停止的轮次发布。重新生成的提供方目录跟随 omp 自身注册表，即对 omp 现状的实测。
- **镜像重建门禁改为记录指纹，而非要求写注释**：`sandbox-image/Dockerfile` 原本有 51 行 `# rebuild:` 散文，每行的唯一作用是改变文件字节，好让 `wrangler` 重新哈希。现在一行 `# image-inputs:` 对全部被复制源与 container block 取哈希，修复方式就是 `bun scripts/check-image-inputs.ts --base origin/main --write`。指纹过期即检查失败；那些散文已删除。
- **Command Code 的模型列表改为实测**：重新生成的目录里该 provider 为 41 个 chat-completions id、12 个 anthropic-messages id、47 个 responses id，取代 18.18.1 快照的 50 / 11 / 35 分布。计数逐字来自 omp 自带注册表，无手工改动。
