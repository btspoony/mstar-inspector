修订记录

2. 独立目录 + 单向生成链

baseline
src/design-system/baseline/reference.html —— 从 .mstar 移入、tracked、CI 可读。 它是设计的权威；文档与 fixture 都从它派生。
tokens（唯一可写源）
src/design-system/tokens/ —— primitive / semantic / component 三层 TypeScript 字面量； tokens.css 由它生成，不再手改。
primitives + patterns
primitives/（现 components/ui/ 迁入）+ patterns/ （GroupCard / ListRow / StepDialog / DataTable / StatusBadge）；业务页只能从 design-system/index.ts 取件。
fixture
fixture.json —— 由 tokens 源生成，供 mstar design-md validate 与 CI 比对；--check 失败即红。
预览页
scripts/build-design-preview.ts → 构建期静态 HTML（不进 runtime）；每个 token、组件、状态、双主题都在一页上。
DESIGN.md
升 v0.5，由 fixture 反哺；frontmatter 与 fixture 一致性由 CI 强制。

方向单向：baseline → tokens → fixture → DESIGN.md。反向修改一律判缺陷。

3. Token 架构：补上缺失的语义层

现在只有 primitive（--gray-800）与 component（--card-border）两层， 中间语义层是空的 —— 组件靠记忆选色阶。这是「看起来像设计系统、用起来不像」的根因。

primitive
--gray-1000、--brand-700、--red-400 … 只代表色值。96 个色阶只保留 32 个被消费的（另加 2 个过渡阶，待 admin 迁移后删除）。
semantic ← 新增
--surface-{page,shell,raised,card,inset,overlay}、 --border-{subtle,default,strong}、 --text-{primary,secondary,muted,faint}、 --tone-{neutral,accent,success,warn,danger}-{bg,border,fg,solid}。 组件只准引用这一层。
component
由语义层组装，数量大幅减少。
乱点现在v0.5
表面命名打架background-100/200/300 与 gray-100/200/300 是同样三个值、两套名字页面只认 surface-* 六档；旧名删除，不留别名
状态表达四个组件各拼各的 badge，边框有无不统一tone-* 五义四属性 + 三档强度
控件高度40 / 32 / 24 散落三处，无名--control-h-xs/sm/md + --row-h-compact/comfort
圆角sm 8 / md 12 / lg 16（16 已无人使用）--radius-control/container/pill，删掉 16
图表色「传任何 -700 都行」，7 个色阶靠注释约束--chart-1…6 封闭序列
双主题light 是暗色的色值镜像，页面未验证两套语义层完整映射，页面同等验收

4. 列表页：一行是一个 App，不是一个仓库

数据模型更正：本系统的单位是 App（GitHub App）。 一个 App 通过 app_installations 被安装到多个账号，每个安装覆盖该账号下的多个仓库。 r1 把 btspoony/mstar-inspector 当成行身份，是错的。

但列表载荷证明不了数量：AppsPayload 只有 App 身份、状态、最近投递与 rejected24h，没有安装数，也没有仓库数。所以 r3 的列表只展示它能证明的字段 —— 仓库范围在应用详情的安装表里，而那里同样只列账号、installation 与最近同步。 编造一个数字比少一列更糟。

门禁检查什么
tokens --checktokens.css 与 TS 源一致；无未定义引用；无未使用变量

design-md validatefrontmatter {path} 全部可解析；light/dark 同名同集合

10. 范围 / 非目标 / 风险

范围内

  • 新建 src/design-system/：tokens 源（三层）、primitives、patterns、baseline、fixture、预览页生成器
  • 三层 token 重构：96 个声明色阶收敛到 26 个存活阶（+2 过渡阶）；teal / pink 整族移除；彻底重命名，不留别名
  • 八个客户侧路由面视觉升级（见 compass「Surface census」）：应用列表 / 应用详情（设置 + 洞察）/ 成员 / 工作区设置 / 登录 / 工作区创建 / 支持 —— 模型提供方是应用设置里的一节，不是独立页面；外加 admin console 一个运营入口
  • 明暗双主题同等验收
  • DESIGN.md 升 v0.5，修掉 3 个 ref 违规，补 button-xs 等缺失条目
  • 五道 CI 门禁；关掉 5 条 design 相关 open issue

非目标

  • 不改信息架构、路由、权限、接口契约、数据模型
  • 不换品牌色、不换字体、不引入 UI 框架、不引入 Storybook
  • 不改暗/亮切换机制（现有 data-theme 手动切换保留）

风险

  • 表面重命名会碰到每一处样式 —— codemod 批量替换 + 边界门禁兜底
  • 视觉回归难自动断言 —— 结构靠 fixture 与门禁，视觉判断交给你在 PR 预览过目
  • 色板瘦身可能砍掉仍在用的阶 —— 每个删除项先跑消费统计，零引用才删
  • 亮色主题同等升级会放大工作量 —— 每个面都要两遍验收，故客户面与运营面分两批交付（2026-11-01）
